# 05 카드/그리드 상태판 (안돈 보드)

실행: `index.html` 을 더블클릭 (file://, 인터넷·CDN 불필요). 파일: `index.html`, `style.css`, `app.js`.

## 표현 방식
- 반응형 CSS Grid(`auto-fill, minmax(310px,1fr)`)로 단계마다 카드 1장. 카드 안에 단계 번호·이름·코드, 검사항목 칩, `palletSlots` 개 슬롯 셀(빈칸/이동/대기/검사/통과/불량), `testPcs` 개 PC 타일(상태색·현재 시리얼·진행률 바), 단계 수율·대기열·평균 사이클.
- 상단 헤더는 안돈 스타일: 현재 시각 + 시뮬 시각, UPH 실적/목표(게이지), 종합 수율, 누적 통과/불량, 라인 내 팔레트, 경보 램프/박스. 하단에 최근 이벤트 티커.
- 상태 변화는 CSS transition(배경/테두리)과 keyframes(통과 팝, 불량 깜빡임, 경보 펄스)로 표현. 수율<90% 또는 대기열≥3이면 카드 경보(적색), 주의는 황색.
- 시뮬레이션: 고정 스텝 0.5초(시뮬 시간), mulberry32 시드 PRNG(`randomSeed`) → 배속과 무관하게 동일 결과 재현. 배속 기본값은 `simulation.speed`. 재생/일시정지, 배속 선택(×1~×50), 초기화 제공.
- 모델: 팔레트가 `arrivalIntervalSec` 마다 투입(최대 `palletCount`), 이동 `conveyorTransferSec`, 검사시간 = `cycleTimeSec`×(0.9~1.1), 불량 확률 `failRate`, `retestOnFail`/`maxRetest` 재검사, 하류 슬롯이 가득 차면 상류 슬롯이 "막힘"(황색 테두리)이 되고 대기열로 집계.
- 수율/UPH 정의: 단계 수율 = 검사 시도 중 통과 비율, 종합 수율 = 최종 통과/(통과+최종 불량), UPH = 최근 15분(시뮬) 통과 수 환산.

## 장점
1. 8단계의 슬롯·PC·수율·대기열을 한 화면에서 한눈에 비교 가능(안돈 보드 용도에 적합).
2. 순수 DOM/CSS라 가볍고 반응형(모바일~대형 TV)이며 단계 수가 바뀌어도 카드가 자동 증감.
3. 경보 기준이 카드 색으로 직관적으로 드러나고 값 변화 시에만 DOM을 갱신해 부하가 낮음.

## 단점
1. 공정 흐름(팔레트가 이동하는 공간적 위치감)이 약하고 카드 순서로만 흐름을 암시.
2. 슬롯 수·PC 수가 많아지면 카드가 길어져 스크롤이 필요.
3. 팔레트 이동 애니메이션이 슬롯 간 점프(페이드/슬라이드)라 연속 이동 표현은 제한적.

## 사용 라이브러리/라이선스
없음 (바닐라 HTML/CSS/JS, 클래식 `<script>`, 외부 폰트·CDN 없음). 직접 작성 코드.

## 데이터 수정 방법
`../data/line.json` 을 수정한 뒤 `../data/sync.sh` 를 실행해 `line.js` 를 재생성. 단계 추가/삭제, `palletSlots`·`testPcs`·`cycleTimeSec`·`failRate`·`items`, `simulation.*`(speed, randomSeed 등), `statusColors` 모두 반영됨. 코드 수정 불필요.

## 검증 기록
- `node --check app.js` 통과. DOM 스텁을 사용한 node 스모크 테스트로 약 50분(시뮬) 실행: 예외 없음, UPH 72·수율 96.3%·통과 52·불량 2.
- 브라우저(헤드리스 Chrome) 실행은 정책상 승인되지 않아 **실제 화면 렌더링/콘솔 에러는 직접 확인하지 못함** — 감독자 검수 필요. 스모크 테스트용 임시 파일은 삭제함.
- ego-browser/find-skills 확인은 생략(브라우저 검증이 차단된 환경).
