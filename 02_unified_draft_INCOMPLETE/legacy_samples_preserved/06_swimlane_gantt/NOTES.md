# 06 스윔레인 + 간트형 타임라인

## 표현 방식
- Canvas 2D 직접 구현(`index.html` + `style.css` + `app.js`). 세로축은 단계(레인) 안에 검사 PC 서브레인, 가로축은 시뮬레이션 시각(기본 최근 15분 스크롤 창, NOW 선이 우측에서 흐름).
- 팔레트 검사 1회 = 막대 1개(시리얼 라벨, 진행중 파랑 / 통과 초록 / 불량 빨강, 재검사는 점선 테두리).
- 레인 헤더: 팔레트 슬롯 점유 게이지(슬롯 수만큼 칸: 파랑=검사중, 노랑=이동·PC 대기), 대기열 칩, PC별 상태 점(idle/busy/pass/fail).
- 막대 클릭 → 해당 시리얼의 전 단계 막대를 강조하고 나머지는 흐리게, 단계 간 곡선 화살표로 경로 연결. 하단 패널에 단계·PC·시각·소요시간 표시. 빈 곳 클릭 시 해제.
- 드래그/휠로 과거 시간 탐색, "실시간으로" 버튼으로 복귀. 재생/일시정지, 배속, 표시 구간, 초기화 컨트롤. KPI: 시각, 투입, WIP, 통과, 불량, NG 횟수, 직행률, UPH.
- 시뮬레이션: 고정 0.5초 스텝, mulberry32(randomSeed)로 재현 가능. 슬롯이 가득 차면 대기열에서 대기 → 컨베이어 이동 → 빈 PC 배정 → 검사(사이클타임 ±15%) → failRate 판정 → retestOnFail/maxRetest 만큼 같은 단계 재검, 초과 시 불량 확정. 팔레트는 palletCount개를 순환 사용.

## 장점
1. 단계별 병목(대기열·슬롯 포화)과 PC 가동 패턴이 시간축 위에서 한눈에 보인다.
2. 특정 시리얼의 전 공정 경로·대기 시간을 추적하기 쉽다.
3. 과거 구간 탐색이 가능하고 외부 라이브러리가 없다.

## 단점
1. 공장 레이아웃/팔레트 물리 이동 느낌은 없다(공간 정보 부재).
2. 막대가 짧은 단계(예: 1단계 30초)는 표시 구간이 길면 라벨이 잘린다.
3. 막대 전체를 매 프레임 재그리므로 매우 긴 구동에서는 점점 무거워진다(필요시 오래된 막대 정리 필요).

## 사용 라이브러리 / 라이선스
없음(순수 JS + Canvas, 클래식 script). 외부 CDN·폰트 없음.

## 데이터 수정 방법
`../data/line.json` 을 수정한 뒤 `data/sync.sh` 로 `line.js` 를 재생성. 단계 수·이름·palletSlots·testPcs·cycleTimeSec·failRate·simulation·statusColors 모두 데이터에서 읽으므로 코드 수정 불필요.

## 검증 상태
`node --check app.js` 문법 검사 통과. 브라우저 실행/콘솔 에러 확인은 환경 정책상 수행하지 못했음(미검증).
