# 02 라인 흐름도 + 대시보드

## 표현 방식
- 상단: SVG 프로세스 흐름도. 단계 N개를 좌→우 노드+화살표로 배치(투입 → 1…N단계 → 출하). 각 노드에 팔레트 슬롯 점유 막대(검사중=파랑, 대기=노랑), 검사 PC 상태 사각형(idle/busy/pass/fail + 진행 막대), PC 수, 대기열 길이/점을 표시. 컨베이어 구간은 점선 흐름 애니메이션 위로 팔레트 사각형이 이동.
- 하단: KPI 7개(투입/통과/불량/수율/UPH(목표 대비)/WIP/재검), 단계별 가동률 막대차트(SVG), UPH 추이 vs 목표 선차트(SVG), 병목 단계 패널, 최근 이벤트 로그. 병목 노드는 빨간 테두리와 "▲ 병목" 표시.
- 시뮬레이션: 고정 스텝(0.25초) 이산 시뮬레이션. `mulberry32(randomSeed)` 로 사이클 변동(±10%)·불량 판정을 결정 → 같은 seed면 프레임레이트/배속과 무관하게 같은 결과. 불량 시 `retestOnFail`/`maxRetest` 로 재검, 초과하면 배출(불량 확정). 병목 = 최근 10분(시뮬) 가동률 + 대기열 가중 점수 최대 단계(3분 이후 판정).
- 컨트롤: 재생/일시정지, 배속(×1~×100, 데이터의 speed 가 기본값), 초기화.

## 장점
1. 흐름과 지표가 한 화면에 있어 병목 원인(대기열·가동률)을 바로 연결해 볼 수 있음.
2. 벡터 SVG라 확대·해상도에 강하고 DOM 요소를 재사용해 가벼움.
3. 단계 수/이름/슬롯/PC 수가 모두 데이터 기반이라 구조가 바뀌어도 자동 반영.

## 단점
1. 팔레트를 슬롯 단위 칸으로만 보여줘 실제 설비 배치(공간감)는 표현하지 못함.
2. 단계가 많아지면(예: 12개 이상) 노드 글자가 viewBox 축소로 작아짐(가로 스크롤 없음).
3. 팔레트 추적은 이동 구간만 점으로 보이고, 단계 내부 이동은 슬롯 색 변화로만 표현.

## 사용 라이브러리 / 라이선스
- 없음 (바닐라 JS + SVG, 외부 CDN·폰트 없음). 폰트는 시스템 폰트 사용.

## 데이터 수정 방법
- `../data/line.json` 을 수정한 뒤 `../data/sync.sh` 를 실행해 `../data/line.js` 를 재생성하면 반영됨. (이 폴더에서는 data/ 를 수정하지 않음)
- 사용 항목: line.targetUph/name/product/shift/taktTimeSec, simulation.*, statusColors, stages[].id/code/name/palletSlots/testPcs/cycleTimeSec/failRate.

## 검증 상태
- `node --check app.js` 통과. 브라우저 실행·콘솔 에러 확인은 이 환경에서 수행하지 못함(헤드리스 Chrome 실행이 승인되지 않음) — 실제로 열어 콘솔 에러가 없는지 별도 확인이 필요함.
- 서버를 띄우지 않는 정적 파일(file://)이라 SPM 등록 대상 아님.
